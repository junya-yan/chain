# CHAIN

**ブラウザで動く、物理チェーンリアクション・パズル。**

**▶ プレイ: https://junya-yan.github.io/chain/**

*他の言語で読む: [English](README.md)*

---

動物は勝手に歩き出す。プレイヤーが直接操作することはなく、あらかじめアイテムを置いて
道を作り、あとはシミュレーションの結果を見守るだけ。

ダイソー「ザ・ゲームシリーズ」の『パズリング』に着想を得ている。個人の習作として
GitHub で公開しているもので、商用利用は目的としていない。詳細は
[権利とクレジット](#権利とクレジット)を参照。

## 動かす

Node.js 20 以降が必要。

```bash
npm install
npm run dev
```

| スクリプト | 内容 |
| --- | --- |
| `npm run dev` | Vite の開発サーバを起動する |
| `npm run build` | 型検査のうえ本番ビルドを作る |
| `npm run preview` | 本番ビルドをローカルで配信する |
| `npm run typecheck` | 型検査のみ実行する |
| `npm run verify` | 全ステージをヘッドレスで検証する（後述） |

## ステージの検証

物理パズルは「解けるはず」と思い込みやすい。各ステージ JSON に想定解 (`solution`) を
書いておくと、次のコマンドがヘッドレスでシミュレーションを再生して確かめる。

```bash
npm run verify
```

チェック内容は 5 つ。

1. 想定解が**配置ルール上そもそも置けるか**（物理的には成立するのに UI では
   置けない、というステージの検出）
2. 想定解で本当にクリアできるか
3. **何も置かなければ失敗するか**（置く意味のないステージの検出）
4. 想定解のアイテム数が `par` 以下か
5. 同じ配置を 2 回流して結果が完全に一致するか（決定論の回帰テスト）

1 のために、配置の可否判定は UI ではなく `src/sim/placement.ts` に置いてある。
UI 側だけに持つと、検証をすり抜ける穴になる。

## 設計

| ディレクトリ | 役割 |
| --- | --- |
| `src/sim/` | 物理とゲームルール。**DOM に一切依存しない** |
| `src/render/` | Canvas 描画 |
| `src/ui/` | 画面と入力 |
| `public/stages/` | ステージ定義 (JSON) |
| `public/sprites/` | キャラクター画像（任意。無ければ手続き的描画） |
| `tools/` | 検証スクリプト |

`src/sim/` が DOM から独立しているおかげで、ブラウザでも Node でも同じ結果になる。
`npm run verify` はこれを利用している。

### 決定論

「同じ配置＝必ず同じ結果」を保証するため、シミュレーションでは

- 乱数を一切使わない（背景の装飾だけは固定シードの擬似乱数を使う。見た目専用）
- 反復は常に配列順。接触の生成順もボディ配列順で決まる
- ホットループで `Math.hypot` を使わない（実装依存の精度を持つため）。`Math.sqrt` は IEEE754 で正確

### 物理

自作の逐次インパルス法による剛体2D（並進＋回転）。SAT で分離軸を求め、参照面／入射面の
クリッピングで接触点を作り、蓄積インパルスをフレーム間で持ち越す。

歩く動物の自走は、速度の直接代入ではなく**摩擦の目標接線速度**として解いている。
直接代入すると次のステップで摩擦ソルバが「滑り」とみなして打ち消してしまうため。
この方式なら坂道で脚が地面を掴み、急すぎる坂では自然に滑り落ちる。

## ステージを足す

`public/stages/` に JSON を置き、`index.json` に id を足すだけ。コードは触らない。
スキーマは `src/sim/types.ts` が唯一の仕様で、ローダが読み込み時に検証する。

```json
{
  "id": "amazon-04",
  "name": "ステージ名",
  "biome": "amazon",
  "brief": "開始時に出す目標の説明",
  "mission": { "type": "reach_goal", "target": "tiger" },
  "protect": ["tiger"],
  "world": { "gravity": 1400, "bounds": { "w": 800, "h": 600 }, "timeLimit": 60 },
  "terrain": [{ "material": "rock", "x": 400, "y": 480, "hw": 420, "hh": 90 }],
  "actors": [{ "type": "tiger", "x": 700, "y": 375, "dir": -1 }],
  "props": [{ "type": "goal", "id": "crown", "x": 70, "y": 272, "hw": 24, "hh": 28 }],
  "inventory": [{ "item": "rope", "count": 1 }],
  "par": 1,
  "hints": ["段階的に出るヒント"],
  "solution": [{ "id": "p0", "item": "rope", "x": 0, "y": 0,
                 "from": { "target": "anchorA" }, "to": { "target": "anchorB" } }]
}
```

座標は左上原点、y は下向き。`solution` は必ず書くこと（検証が効かなくなる）。

### ステージ設計で効いてくる数値

歩く動物は跳べないので、地形は次の制約を強く受ける。

| 挙動 | 値 | 意味 |
| --- | --- | --- |
| 歩行速度 | 62 px/s | |
| 登れる段差 | 13 px | これを超えると壁とみなして引き返す |
| ロープ・ハシゴ登り | 52 px/s | 縦移動の手段 |
| 上端からの飛び移り | vx 95 / vy 70 | 隣の足場へ移れる距離の上限を決める |
| 掴める距離 | 横 20 px / 縦 20 px | 当たり判定（8x12）からの余裕。これを超えると届かない |

板 (`platform`) は幅 72 px。**これより広い隙間は板 1 枚では渡れない**（両端が地形に
乗らないと落ちる）。縦の移動が必要な地形にはロープかハシゴを用意すること。

ハシゴ (`ladder`) は長さ 160 px。掴まれるのは動物の高さに一番近い桟なので、**下端は
動物の胴（中心 ±32 px）に届かせる**こと。上端では進行方向へ飛び移るが、飛び移りは
弾道で上向きの初速は 70 しかない。**上端は乗り移りたい足場より 30〜60 px 上に、
横のずれは 20〜30 px に収める**こと。どちらを外しても届かない。

吊り橋 (`bridge`) はロープと同じく 2 点を指定して架ける。**たわみの深さは
「架けた 2 点の距離 x 0.18」**で、乗せた物では大きく変わらない（踏み板が伸びない
ため）。桁は 60 px ごとにしか折れない。これより細かくすると、足元の板が動物より
軽くて動き回るので踏ん張れず、渡りきれなくなる（見た目の板は描画側で刻んでいる）。
架け渡せる距離は実測で 300 px あたりが上限。

風船はロープが張りきる高さまでしか上がらない。つまりロープの長さ＝配置時の 2 点間距離が
風船の最終的な高さを決める。

風船 1 個の正味の浮力は 7000（重さに直すと 5.0）。**ハシゴは 5.2 あるので、風船 1 個では
持ち上がらず 2 個で上がる。** ロープもノード 1 個 (12 px) につき 0.1 の重さを持つので、
長く垂らすほど余裕は減る（風船 2 個なら 300 px 程度までは吊れる）。

## キャラクター画像

描画は 3 段構えで、用意があるものから順に使われる。

1. **リグ**（`public/sprites/rig.json`）— 1 枚絵を部位に切り分け、関節を回して動かす
2. **スプライトシート**（`public/sprites/manifest.json`）— コマ割りの画像
3. **手続き的描画** — 画像が無くてもこれで遊べる

**GIF は使わないこと。** 歩きのコマは実際の移動距離に同期しており、さらに 2x/4x の
早送りと一時停止がある。GIF は自前の時計で動くので絵と物理がずれる。透過も 1bit
なので暗い背景で輪郭が汚くなる。詳細は
[docs/sprites.md](docs/sprites.md)、
画像生成AIへの指示は [docs/ai-prompt.md](docs/ai-prompt.md)。

### 生成AIの「シート風の絵」から使えるシートを作る

画像生成AIはコマ間の一貫性を保てず、背景や枠・ラベルを焼き込んだ「ポスター」を
出しがち。`tools/extract-frames.py` はそこから使えるシートを起こす。

```bash
python3 tools/extract-frames.py art-source/tiger.png public/sprites/tiger.png
```

- 外周からの塗りつぶしで、焼き込まれた背景を抜く（キャラの濃い輪郭線が堰になる）
- 靴が接している地面は、セル下端から採った色見本で狙い撃ちして消す
- 最大の連結成分だけ残して、岩などの残骸を落とす
- **背丈と足元の高さを全コマで揃える**（生成AIはここが揃わない。揃えないと歩行がガタつく）

現在 `public/sprites/tiger.png` はこの手順で作られている（11 コマ）。
閾値は絵ごとに調整が要る。トラの絵での上限は実測で次のとおり。

| 定数 | 値 | 超えると起きること |
| --- | --- | --- |
| `TOLERANCE` | 34 | 40 以上でキャラの輪郭を突き抜け、体が分断される |
| `GROUND_MATCH` | 10 | 14 以上で靴から削れはじめる |

## アイテム

| アイテム | 挙動 |
| --- | --- |
| 板 | 足場にも斜面にもなる。傾ければ物が滑る |
| 吊り橋 | 2 点に架け渡す。自分の重みでたわむ。動物が渡れる |
| ハシゴ | 動物がつかまって登る。動物とはすり抜ける。重いので吊るには風船が 2 個いる |
| 風船 | 上へ浮かぶ。繋いだ物を吊り上げる。棘や爆風で割れる |
| ロープ | 2 点を繋ぐ。動物が登れる。火が付くと端から燃え進み、やがて切れる |
| 爆弾 | 火が付くと少し遅れて爆発する。鳥を飛び立たせ、物を吹き飛ばす |
| ばね | 触れた物を勢いよく弾き返す |
| 錘 | とても重い。落ちて物を押しつぶす |
| 滑車 | ロープが乗り、力の向きを変える |

### 原作との関係

ダイソー「ザ・ゲームシリーズ」の『パズリング』（No.29〜31）に**着想を得ているだけ**で、
原作とは無関係の別作品。原作からは何ひとつ持ち込んでいない。

- 名称を使っていない（原作名を避けて `CHAIN` としている）
- 画像・音・コードを一切流用していない
- ステージ構成・アイテムの挙動・物理の実装はすべて独自に設計したもの

原作は Windows 95/98/Me/XP 向けで、現在は入手も実行も困難。挙動を参照できないため、
再現ではなく着想元として扱っている。
